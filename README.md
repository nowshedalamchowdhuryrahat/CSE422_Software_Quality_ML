# Software Quality Prediction Using Machine Learning

A BRAC University CSE422 (Artificial Intelligence) lab project that explores software quality data using supervised machine learning and unsupervised clustering.

## Project Overview

The goal of this project is to investigate whether software metrics can be used to predict a software quality category. The target column is `Quality_Label`, with three classes:

- `High`
- `Medium`
- `Low`

The notebook also applies K-Means clustering to explore the data without using the target labels during cluster formation.

## Dataset

The supplied CSV contains **1,600 rows and 9 columns**: eight input features and one target column.

| Column | Description / type |
|---|---|
| `Lines_of_Code` | Numeric software metric |
| `Cyclomatic_Complexity` | Numeric software metric |
| `Num_Functions` | Numeric software metric |
| `Code_Churn` | Numeric software metric |
| `Comment_Density` | Numeric software metric |
| `Num_Bugs` | Numeric software metric |
| `Has_Unit_Tests` | Categorical input (`Yes` / `No`) |
| `Code_Owner_Experience` | Numeric software metric |
| `Quality_Label` | Target class (`High`, `Medium`, or `Low`) |

The dataset has missing values in `Lines_of_Code`, `Code_Churn`, and `Comment_Density`. The notebook currently uses median imputation for these columns and encodes `Has_Unit_Tests` as a binary feature.

### Class distribution

## Methods in the Notebook

### Exploratory data analysis (EDA)

- Dataset shape, column types, and descriptive statistics
- Target-class distribution chart
- Correlation heatmap
- Feature relationships and distributions, including unit testing, code-owner experience, bug counts, cyclomatic complexity, comment density, and lines of code

### Preprocessing and splitting

- Median imputation for selected numeric columns
- Binary encoding of `Has_Unit_Tests`
- Encoding of the target labels
- Feature scaling for models that require it
- Stratified train/test split using an 80% training set and 20% test set

Review the notebook's preprocessing order before relying on final evaluation scores: fit imputation and scaling steps using training data only to avoid data leakage.

### Models

The current notebook includes:

- Gaussian Naive Bayes
- Logistic Regression
- Neural Network (TensorFlow/Keras)
- K-Means clustering (unsupervised learning)

K-Means is an unsupervised method. Any comparison to the known quality labels is a post-hoc analysis and should not be interpreted as ordinary supervised classification performance.

### Evaluation

The notebook reports or visualizes metrics including:

- Accuracy
- Weighted precision, recall, and F1-score
- Confusion matrices
- One-vs-rest ROC curves and AUC summaries
- A model comparison table and best-model summary
- K-Means elbow plot and a PCA-based cluster visualization

Results are generated by running the notebook. They are not hard-coded in this README.

## How to Run

### Option 1: Google Colab (recommended for beginners)

1. Open [Google Colab](https://colab.research.google.com/).
2. Upload and open the `.ipynb` notebook.
3. Upload `software_quality_dataset.csv` when the notebook reaches its file-upload cell.
4. Run the notebook cells from top to bottom.
5. Review the generated charts, evaluation metrics, and model comparison.

### Option 2: Run locally

1. Install Python 3.10 or 3.11 in a virtual environment.
2. Install the packages listed in `requirements.txt`:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Start Jupyter:

   ```bash
   python -m pip install notebook
   jupyter notebook
   ```

4. Open the notebook and ensure `software_quality_dataset.csv` is in the working directory. The current notebook includes a Google Colab upload cell (`google.colab.files`); when running locally, replace that upload step with a normal local-file workflow.
5. Run all cells from top to bottom.

TensorFlow compatibility depends on the Python version and operating system. If installation fails, use Google Colab or choose a TensorFlow-supported Python environment.
